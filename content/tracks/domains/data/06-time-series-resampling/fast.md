# Fast path: what's different in C++

- **`<chrono>`.** C++ has typed time: `std::chrono::milliseconds`, `time_point<system_clock, milliseconds>`, `duration_cast`. `std::chrono::floor<std::chrono::hours>(tp)` is the floor that `align_down` implements, and since C++20 `std::chrono::sys_time`, `year_month_day`, `zoned_time` handle calendars and time zones. This challenge uses plain `int64_t` because the *integer* pitfalls (overflow, truncating division) are the same underneath, and because data pipelines carry raw epoch numbers.
- **Signed overflow is undefined; unsigned wraps.** `int64_t` arithmetic that overflows lets the compiler assume it did not happen and delete your checks; `-fsanitize=undefined` (or `-ftrapv`) catches it, and `__builtin_add_overflow` / `__builtin_mul_overflow` (GCC, Clang) give a checked operation, as `std::add_sat`/`std::mul_sat` (C++26) will. The unsigned-difference trick here is the portable alternative for `a <= b`.
- **`std::midpoint`, `std::lerp`.** `std::lerp(a, b, t)` is the standard blend (exact at `t = 0` and `t = 1`, no overflow problems from the form `a + t * (b - a)` for finite inputs the way `fma` would)... the point of writing `v0 * (1 - f) + v1 * f` here is to see why the library function exists.
- **Time-series databases and libraries.** pandas `resample()`/`asfreq()`, Prometheus `rate()`/staleness (the `max_gap` idea: a series with no sample for 5 minutes is *stale*, not constant), InfluxDB `aggregateWindow`, kdb+ `asof` joins, Apache Arrow compute. For C++: **Arrow**, **xtensor**, **Boost.Histogram**; and ClickHouse's `toStartOfInterval` is `align_down` with calendar logic.
- **Why a forward-only pointer is also cache-friendly.** The two arrays are read sequentially, so the hardware prefetcher keeps up; a binary search per grid point jumps around and is several times slower for the same big-O in practice for dense data. For sparse samples and a huge grid the opposite holds: iterate over the samples and write the runs of the grid they cover.
- **Calendar buckets are not fixed-width.** Days with DST changes have 23 or 25 hours, months have 28 to 31 days: fixed-width `width` only suits "every N seconds/minutes/hours" (UTC). Calendar bucketing needs the calendar library and a policy for the missing/duplicated local hour.
