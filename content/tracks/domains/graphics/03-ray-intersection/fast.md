# Fast path: what's different in C++

- **Production ray tracers.** **Embree** (Intel), **OptiX** and **DXR/Vulkan RT** (GPU hardware), **Bullet/PhysX/Jolt** for game physics raycasts. They all intersect millions of rays per second by combining the tests you wrote with a **BVH** (bounding volume hierarchy) built from the same `Aabb` slab test, and with SIMD packets that test 4 to 16 rays at once. The ray-box test in this lesson is the hot loop of every BVH traversal.
- **Branchless slabs.** The version with `min`/`max` and no `if (d == 0)` relies on IEEE infinities (`1/0 = inf`) and on `std::min`/`std::max` ordering NaN consistently; it is the standard fast version, and it has the `0 * inf` problem when the origin is exactly on a slab boundary. Production code precomputes `1/d` once per ray and either accepts that corner or handles it with careful `min`/`max` argument order.
- **Watertight intersection.** Moller-Trumbore can let a ray slip through the exact shared edge of two triangles (rounding makes both reject it). **Woop, Benthin and Wald's** watertight algorithm (2013) transforms the triangle into the ray's coordinate system and tests the edge functions exactly with a fallback to double precision. This is what makes meshes leak-proof.
- **Self-intersection.** After a hit you spawn a new ray (shadow, reflection) from `point`; rounding can put it slightly below the surface so it hits itself ("shadow acne"). Cures: a `t_min` epsilon (as here), or offsetting the origin along the normal, or **Ray Tracing Gems'** "robust offset" using the floating-point error bounds of the hit position. The `t_min`/`t_max` window in the API exists for exactly this.
- **`float` vs `double`.** GPUs use `float`; the stable sphere discriminant matters even more there (24-bit mantissa). `std::fma` helps compute `a*b - c*d` accurately (Kahan's trick), another form of the same cancellation cure.
- **Math details.** `std::hypot` for lengths (C++17's three-argument overload is used by the helper header), `std::isfinite`, `std::fabs`; the standard library has no vector type, so engines bring their own (glm, Eigen, DirectXMath) or use `std::array<double, 3>`.
