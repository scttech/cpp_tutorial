# Fast path: what's different in C++

- **Libraries.** **diff-match-patch** (Google; character-level and semantic cleanup, ports for every language), **dtl** (a header-only C++ diff template library that implements Myers/Wu), **libgit2**/**xdiff** (Git's engine: Myers by default plus *patience* and *histogram* variants); **difflib** in Python is the model. GNU `diff`/`diff3` and `patch` are the reference implementations your output is compared with in the real world.
- **The linear-space refinement.** The version you wrote stores `O(D^2)` history. Myers' paper's second algorithm finds the **middle snake** (run the search from both ends at once until the two frontiers overlap), splits the problem there and recurses, using `O(N + M)` memory and the same time bound. That is what production code uses; the trick is also the basis of Hirschberg's linear-space LCS.
- **Better-looking diffs, not shorter ones.** Minimal is not always readable: Myers can align a `}` of one function with a `}` of another. **Patience diff** (Bram Cohen) anchors on lines that are unique in both files, **histogram diff** (jgit, git's `--histogram`) extends it with frequency counts; `git diff --diff-algorithm=patience` and `--minimal` expose them. Many tools also post-process hunks to slide boundaries to blank lines ("indent heuristic").
- **Hashing lines.** Comparing strings repeatedly is the hot cost (the megabyte-line test). Production diffs first map each distinct line to an integer id with a hash table (`std::unordered_map<std::string_view, int>`), then run the algorithm on integer arrays, which also makes whitespace-insensitive modes (`-w`, `-b`) a matter of normalising before hashing.
- **Ranges and spans.** `Lines` here is a `std::vector<std::string>`; a faster design keeps one `std::string` for the whole file and `std::string_view` lines into it (zero copies; the views must not outlive the buffer). C++20 `std::ranges::mismatch` and `std::ranges::equal` express the trimming loops; `std::span<const Edit>` is the natural parameter type for a script.
- **Word- and character-level diffs** run the same algorithm on tokens: split lines into words (or code points), diff those, and render with colour (`git diff --word-diff`, GitHub's inline highlighting). Anything that has a notion of "sequence of comparable things" can be diffed: ASTs (GumTree), JSON (`jd`), DNA sequences, and rsync's rolling checksums for binary data.
- **Three-way merge** (`diff3`, `git merge`) applies two diffs against a common ancestor and reports conflicts where the changed regions overlap: it is built on exactly this function.
