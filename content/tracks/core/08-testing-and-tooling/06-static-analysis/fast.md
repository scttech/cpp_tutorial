# Fast path: what's different in C++

- **Static analysis is a normal part of a C++ build.** Compiler warnings (`-Wall -Wextra ...`) first; then **clang-tidy** (checks by family: `bugprone-`, `performance-`, `modernize-`, `readability-`, `cppcoreguidelines-`, `clang-analyzer-`; configured in `.clang-tidy`; needs `compile_commands.json`, which CMake writes with `CMAKE_EXPORT_COMPILE_COMMANDS=ON`; `--fix` applies suggested rewrites; `run-clang-tidy` runs it in parallel; `CMAKE_CXX_CLANG_TIDY` runs it during the build) and **cppcheck** (own parser, few false positives, array bounds, uninitialized members, leaks; `--enable=...`, `--project=compile_commands.json`).
- **Other free tools**: the Clang Static Analyzer (`scan-build`, also available as `clang-analyzer-*` checks in tidy), **include-what-you-use** (headers), **Infer** (Meta), **CodeQL** (free for open source), **Coverity Scan** (free for open source), **cpplint** (Google style), **clang-format** (layout; later lesson). SonarQube has a community edition.
- **Typical findings and what they mean**: `bugprone-use-after-move` (a moved-from object is read), `bugprone-integer-division` (an `int` division used as a `double`), `bugprone-branch-clone` (copy-paste: identical branches), `bugprone-suspicious-*` (a shape that looks like a typo), `performance-unnecessary-value-param` / `-for-range-copy` / `-faster-string-find` (needless copies), `modernize-use-nullptr` / `-use-override` / `-use-auto` (modern idioms), `readability-container-size-empty` (`empty()` instead of `size() == 0`), `cppcoreguidelines-pro-type-member-init` (uninitialized members), `clang-analyzer-*` (null dereference, leaks, use after free on a path).
- **Policy beats perfection**: enable what your team agrees on, fix the existing findings or record them as a baseline, then fail CI on **new** ones. A check that is always ignored is noise; remove it from the config rather than suppressing it everywhere.
- **Suppress narrowly**: `// NOLINT(check-name)` or `// NOLINTNEXTLINE(check-name)` with a reason; `// cppcheck-suppress id`. Never a blanket `NOLINT`.
- **Static vs dynamic**: analyzers see code that never ran, but guess; sanitizers and tests see what really happens, but only on the paths that run. Use both.
