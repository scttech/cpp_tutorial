# Fast path: what's different in C++

- **What real rasterizers do.** GPUs evaluate the edge functions for a whole tile (8x8 or 16x16 pixels) at once and step them incrementally (`w += dy` per pixel in x, `w += dx` per row) instead of recomputing the multiplications; the **top-left rule** is specified in Direct3D 10+ and Vulkan, and sub-pixel precision is 4 to 8 bits (the 28.4 format here is the classic). Software renderers (SwiftShader, Mesa's llvmpipe, Skia's CPU backend, `stb_truetype`) use the same ideas with SIMD.
- **Incremental vs formula.** Bresenham's loop avoids the division: keep an error term, add `2*DY` per step, subtract `2*DX` when it passes the threshold. It is the same pixel set as the formula (the tests prove it for this rule) and 3x faster per pixel; the formula wins when you want to jump into the middle of a line, which clipping does.
- **Clipping choices.** For lines the standard algorithms are **Cohen-Sutherland** (outcodes) and **Liang-Barsky** (parametric); both clip the *geometry* and then draw the clipped segment, which can change the rounding of the pixels that remain. GPUs avoid this problem for triangles by **not clipping at all** inside the guard band: they rasterize against the viewport with the full-size edge functions, as you do here. Only the near plane must be clipped geometrically (`w <= 0`).
- **Integer types.** `int32_t` coordinates with `int64_t` intermediates is the classic recipe. `__int128` (GCC/Clang) or `std::mul_hi`-style tricks extend it. The explicit coordinate limits in the API are the honest alternative to silently overflowing; in the C++ standard signed overflow is undefined, and `-fsanitize=undefined` finds it.
- **`std::span` and `Canvas`.** A canvas is a non-owning 2D view of memory (see the matrix challenge in the Data track): `std::mdspan` (C++23) is the standard version. The unchecked `plot()` here is deliberate so that the guard-byte tests can catch out-of-bounds writes, which in a real renderer are the most common source of crashes and security bugs.
- **Antialiasing.** What you wrote is a binary coverage test. Antialiased lines (Wu's algorithm, Xiaolin Wu 1991) and MSAA (several sample points per pixel, each tested with the same edge functions) generalise it; analytic coverage (as in Skia/FreeType) computes the exact area fraction.
