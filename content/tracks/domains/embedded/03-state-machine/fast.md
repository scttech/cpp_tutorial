# Fast path: what's different in C++

- **Plain function pointers instead of `std::function`.** `std::function` can allocate and costs an indirect call plus a type-erased manager; a `void (*)(Ctx&)` is one machine word that may live in flash and be called in two instructions. Captureless lambdas convert to function pointers implicitly (`+[](Ctx& c) { ... }` or direct assignment as in this exercise), which is why the tables can use readable inline lambdas.
- **`const` tables go to flash.** A `static const Transition table[] = {...}` of constants is placed in read-only memory by the linker: zero RAM, and a bug cannot overwrite your rules. `constexpr` tables can also be *checked at compile time* (`static_assert` that no row is shadowed, that every state is reachable).
- **Templates over `enum class`.** The engine is generic in the state and event types; with `enum class` they cannot be mixed up (passing an event where a state is expected is a compile error) and cost one byte each. In C a state machine usually means `int state` and comments.
- **Alternatives.** `std::variant` + `std::visit` state machines (each state a type, transitions return the next state) give compile-time checking of the transitions but are harder to table-drive and review. Boost.SML and Boost.MSM provide a DSL with the same semantics (entry/exit, guards, internal transitions, wildcard). UML statecharts add *hierarchical* states, which this exercise leaves out.
- **Guards must be pure.** A guard that changes state breaks the "first passing row" reasoning and makes the order of rows observable in strange ways. The tests count guard calls precisely because real firmware reads hardware in guards.
