# Fast path: what's different in C++

- **Bit-fields (`struct { unsigned parity : 2; }`) are the wrong tool for registers.** The language leaves their layout (bit order, packing, padding, signedness of plain `int` fields) to the implementation, so a datasheet cannot be mapped onto them portably. C++ firmware uses masks and shifts wrapped in types, exactly as here; Rust has the `bitflags` and `tock-registers` crates, Zig has packed structs with defined layout.
- **`volatile` is for the real register, not for this layer.** On a device the register is `*reinterpret_cast<volatile std::uint32_t*>(0x4000'0000)` and every access really reaches the bus. The `Register` class here simulates that so the access counts can be tested; a real version would hold a `volatile T*` and the same operations would compile to a single `ldr`/`str` pair because `get`/`insert` are `constexpr` and inline: **no abstraction cost**.
- **`constexpr` + templates = datasheet checked at compile time.** `static_assert(Offset + Width <= digits)` costs nothing at run time, and `static_assert(F::fits(5))` can reject a constant that does not fit. This is the zero-overhead principle: you pay for what you use.
- **Fold expressions (C++17)** turn a parameter pack into a single expression. Before C++17 `modify` needed recursion or an `initializer_list` trick.
- **Why not read-modify-write everywhere?** Registers with read side effects (clear-on-read status, FIFO data), write-only registers (a read returns garbage or traps) and W1C flags all break on an innocent-looking `reg |= x`. Naming the operation (`write_one_to_clear`) is how the type system carries the datasheet's rules.
