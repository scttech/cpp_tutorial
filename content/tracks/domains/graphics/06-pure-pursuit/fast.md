# Fast path: what's different in C++

- **Real stacks.** **ROS 2 Navigation (Nav2)** has a Regulated Pure Pursuit controller (curvature-based speed regulation exactly like the one here, plus obstacle checks); **Autoware** and **Apollo** use pure pursuit and **Stanley** (steering from the cross-track error and heading error of the *front axle*) for cars; **MPC** controllers (optimising over a horizon with a vehicle model, e.g. via **acados** or **CasADi**) replace both when you need constraints. Pure pursuit is the one you can write on a napkin and debug in a field.
- **Units and types.** Real code uses strong types: `std::chrono::duration` for `dt`, and libraries like **mp-units** or **Boost.Units** for metres, radians and seconds, so that you cannot pass degrees where radians are expected. This lesson uses `double` with comments because the algorithm is the point, but a `wrap_angle(degrees)` bug is the most common bug in robotics code.
- **`std::numbers::pi`** (C++20, `<numbers>`) replaces the hand-written constant; `std::remainder(a, 2*pi)` returns a result in `[-pi, pi]` and is the one-liner version of `wrap_angle` (check the boundary behaviour you want: it picks the even multiple at exactly `pi`). `std::fmod` keeps the sign of the dividend, which is why `wrap_angle` needs the two adjustments.
- **Real-time rules.** A control loop runs on a deadline: no allocations, no exceptions, no locks in `step()` (the tests check zero allocations). `Path` owns a `std::vector` and is built once, outside the loop; `step()` only reads it. Hard real-time systems also avoid `std::sin`/`cos` jitter by using lookup tables or fixed iteration-count approximations.
- **Frames.** Everything here is in one world frame with the pose as `(x, y, theta)`. Real robots chain frames (map, odometry, base link) with transforms (`tf2`, `Sophus::SE2`); a transform of the carrot into the robot frame is a rotation by `-theta`, as in `step()`.
- **Why the lookahead matters.** A short lookahead tracks tightly but oscillates; a long one is smooth but cuts corners (the square-path test measures that cut). Tuning the lookahead as a function of speed (`L = k * v`) is the standard fix, and the reason `Params::lookahead` is a parameter, not a constant.
