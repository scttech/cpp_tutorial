# Fast path: what's different in C++

- **Real logging libraries.** **spdlog** (the usual choice: fast, header-only, async, sinks, `fmt`-based), **Boost.Log**, **glog**/**Abseil logging**, **Quill** and **NanoLog** (nanosecond-latency, binary formats decoded offline), **log4cplus**, and for structured logging **spdlog** with a JSON formatter or **tracing**-style libraries (Rust's `tracing`, Go's `slog`, Python's `structlog`). Go's `log/slog` (2023) is almost exactly this lesson's API: records with a level, message and key/value attributes, handlers that format them, `With()` for context.
- **`std::format` and `std::print`.** C++20/23 `std::format("{}", x)` replaces `printf`/streams for human text, and `std::to_chars` is the right tool for numbers inside a hand-written serialiser: locale-independent, allocation-free, and shortest-round-trip for floating point since C++17 (the same algorithm as Ryu/Grisu/Dragonbox under the hood). JSON libraries (**nlohmann/json**, **RapidJSON**, **simdjson** for parsing, **Glaze**, **yyjson**) hide exactly the escaping and number rules you just wrote.
- **`std::chrono` for time.** C++20 `<chrono>` has `sys_time<milliseconds>`, `year_month_day`, `hh_mm_ss` and `std::format("{:%FT%T}Z", tp)`, i.e. the calendar arithmetic of this lesson, and `time_zone` support. The test uses it as an independent oracle. The standalone algorithm is still worth knowing: it is `constexpr`, needs no tables, and is what libc++ and libstdc++ use inside.
- **Hot-path logging is a different problem.** `std::string` building and virtual calls cost hundreds of nanoseconds, which is too slow for a loop that logs per packet. High-performance loggers write a compact binary record to a per-thread ring buffer on the hot thread (timestamp via `rdtsc`/`clock_gettime(CLOCK_MONOTONIC_COARSE)`, arguments copied raw) and a background thread formats and writes. The disciplines from this lesson (escape on output, never trust bytes) move to the formatter thread.
- **Ordering and loss.** Real loggers are asynchronous; they need a bounded queue and a policy when it fills (block, drop oldest, drop newest and *count* the drops, which is what the suppression counter here is a small version of), and a way to flush on `SIGTERM` or crash. Never `new` or take a global lock inside a signal handler.
- **Security.** *Log injection*: a user-supplied `"\nINFO admin logged in"` forges a line in a plain-text log; JSON escaping is the cure, which is half the reason to log JSON. Do not log secrets, tokens or full request bodies; redact by *field name* in the logger so one forgotten call cannot leak. Truncate attacker-controlled values (the line cap) so one request cannot fill the disk.
