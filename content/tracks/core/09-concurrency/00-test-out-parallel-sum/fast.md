# Fast path: what's different in C++

- **Threads are in the library**, not the language: `#include <thread>`, link with `-pthread`. `std::thread t(f, args...)` starts running at once; the arguments are **copied** into the new thread (use `std::ref(x)` or a lambda capture by reference to share a variable, and make sure it outlives the thread). `std::jthread` (C++20) joins in its destructor and supports cooperative cancellation (`std::stop_token`); a `std::thread` that is still joinable when destroyed calls `std::terminate`.
- **A data race is undefined behavior**: two threads, same memory location, at least one writes, no synchronization between them. Not "a wrong answer sometimes": anything. Avoid sharing; give each thread its own slot (a `std::vector<T>` indexed by thread, then combine after `join()`) rather than locking inside a hot loop.
- **Partitioning**: `n / k` values per thread and the first `n % k` threads get one more. Use `std::min(k, n)` workers. For a real speedup, size the parts so that a thread does thousands of operations per task, and keep per-thread results on separate cache lines (false sharing) if they are updated often.
- **Library help**: `std::transform_reduce` / `std::reduce` with `std::execution::par` (C++17 parallel algorithms, needs a TBB-style backend in the standard library), OpenMP (`#pragma omp parallel for reduction(+:sum)`), or a thread pool; for sums of integers, accumulate into a wider type (`0LL`).
- **ThreadSanitizer** (`-fsanitize=thread`) finds data races and lock-order inversions at run time, 5-15x slower; it cannot be combined with AddressSanitizer.
