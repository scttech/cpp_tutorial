# Fast path: what's different in C++

- **`std::bitset` and `vector<bool>` are not the right tools here.** `std::bitset<N>` has a size fixed at compile time, which a filter sized from `n` and `p` at run time cannot use; `vector<bool>` is a famous special case that is not a container of `bool` and gives you no access to its words. The idiomatic answer is a `std::vector<std::uint64_t>` and shifts and masks: one cache line holds 512 bits, and C++20's `<bit>` header provides `std::popcount`, `std::countr_zero`, `std::bit_ceil` as portable wrappers over single CPU instructions. Java has `BitSet`, Python has `int` or `bytearray`, Rust has `bitvec`; C++ gives you the building blocks.
- **Bytes are `std::uint8_t`, positions are `std::size_t`, and hashes are `std::uint64_t`:** the arithmetic `h1 + i * h2` relies on **unsigned wrap-around**, which C++ guarantees (signed overflow is undefined behaviour). Using `int` or `long` for a hash is a classic bug.
- **`std::span<const std::uint8_t>`** (C++20) accepts a vector, an array or a pointer-and-length without copying, and it carries the size, which is what makes `from_bytes` safe to write: you check `data.size()` before touching `data[i]`. Compare with C's `const uint8_t* p, size_t n` pairs where mismatches cause CVEs.
- **Parsing untrusted input: validate, then allocate.** The "claimed size" in a header is attacker-controlled; the *actual* size is `data.size()`. Many real vulnerabilities (and denial-of-service bugs) come from the order of those two steps. `std::optional` is the right return type for "this might not parse": no exceptions, no sentinel values.
- **Where Bloom filters live in real systems:** Chrome's Safe Browsing (is this URL malicious?), Bigtable/Cassandra/RocksDB (skip SSTable files that cannot contain a key), Bitcoin SPV clients, CDNs ("one-hit wonder" filtering before caching). Variants: *counting* Bloom filters (counters instead of bits, support deletion), *cuckoo* filters (deletion, better space at low rates), *blocked* Bloom filters (all `k` bits in one cache line, 2 to 3 times faster).
