# Fast path: what's different in C++

- **Callables as templates.** `template <class F> bisect(F f, ...)` is instantiated once per lambda, so `f` is inlined into the loop: this is why `std::sort` with a lambda beats `qsort` with a function pointer. `std::function` type-erases the callable (a virtual call and often a heap allocation); use it only when you must store callables of different types.
- **`std::midpoint` and `std::lerp` (C++20).** `std::midpoint(a, b)` is the overflow-free average (it is `a + (b - a) / 2` done carefully, also for pointers and integers); `std::lerp(a, b, t)` guarantees `lerp(a, b, 0) == a` and `lerp(a, b, 1) == b` exactly, and is monotonic: the same concerns as the blend in this challenge.
- **Binary search in the standard library.** `std::lower_bound`/`std::upper_bound` work on any sorted range with random access in `O(log n)`; for `std::set` use the member functions (`s.lower_bound(x)`), because the free functions walk the tree node by node in `O(n)` on non-random-access iterators.
- **Libraries.** Interpolation and solvers: **GSL** (`gsl_interp_cspline`, `gsl_root_fsolver_brent`), **Boost.Math** (`boost::math::tools::toms748_solve`, `bracket_and_solve_root`, `cubic_b_spline`, `barycentric_rational`), **Eigen's** unsupported Splines module, **Ceres** for non-linear least squares. In Python, `scipy.interpolate` and `scipy.optimize.brentq` are the reference. The method production code usually picks is **Brent's**: bisection's guarantee with the secant method's and inverse quadratic interpolation's speed, no derivative required.
- **Which spline?** Natural splines wiggle at the ends (the tests avoid the ends for `sin`); *not-a-knot* and *clamped* (given end slopes) boundary conditions fit better when you know more. For data with plateaus, a cubic spline overshoots and a *monotone* interpolant (PCHIP, Fritsch-Carlson) does not: never use a plain spline on a CDF or a price curve you will invert.
- **Floating-point equality.** `fm == 0.0` is an honest test only because a function can return exactly zero at a double; do not use it for anything computed with accumulated rounding. The stopping rule `|step| <= tol * max(1, |x|)` mixes absolute and relative tolerance on purpose: a pure absolute one never fires for a root near `1e12`.
