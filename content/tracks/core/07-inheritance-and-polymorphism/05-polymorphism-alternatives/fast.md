# Fast path: what's different in C++

- **Virtual dispatch costs**: an extra pointer per object (vptr), an indirect call (hard to inline, and a possible branch misprediction), and in practice a heap allocation per polymorphic object plus pointer chasing. It is usually fine, and it is exactly what Java and C# do for *every* object. C++ lets you choose.
- **`std::variant<A, B, C>`** is a type-safe tagged union: it stores one value *inside itself* (size = largest alternative + a tag). `std::visit(visitor, v)` calls the visitor with the held alternative; the visitor must accept *every* alternative (compile error otherwise). A `std::vector<variant<...>>` is contiguous: no per-element allocation. Compare Rust's `enum` and `match`. An `Overloaded` helper (an inheritance from lambdas with `using Ts::operator()...`) is the idiom for per-alternative lambdas. `std::get<T>(v)` throws `std::bad_variant_access` for a wrong guess; `std::get_if<T>(&v)` returns null. A variant can become *valueless by exception* if a move throws during assignment: a rare corner.
- **CRTP** (`class D : public Base<D>`): *static polymorphism* and mixins. The base calls derived members through `static_cast<const D&>(*this)`: resolved at compile time and inlined, no vptr, no virtual. Used by the standard library (`std::enable_shared_from_this`, `std::ranges::view_interface`). C++20 concepts and C++23 "deducing this" (`this auto&& self`) replace much of it. Make the base's constructor private and `friend Derived;` to catch the wrong-derived-class mistake.
- **Type erasure** = a value type with a template constructor and a hidden virtual interface (the *concept/model* idiom). `std::function`, `std::any`, `std::shared_ptr`'s deleter and `std::move_only_function` are type-erased. The user's types need no base class: it is *non-intrusive*, the opposite of inheritance. Beware: a forwarding-reference constructor `template <class T> AnyShape(T&&)` also matches `AnyShape&` and hijacks the copy constructor: constrain it with `requires (!std::same_as<std::remove_cvref_t<T>, AnyShape>)`.
- **Customization by free function** (`area(shape)`, like `begin(c)` and `swap(a, b)`): found by argument-dependent lookup. Inside a class that has a *member* of the same name, an unqualified call finds the member and ADL is not performed: call through a free helper function.
- **The expression problem**: virtual functions make adding *types* easy and adding *operations* hard; variant + visit the reverse. Neither is better in general.
- **When static polymorphism wins**: the type is known at compile time, you have many objects, or the function is tiny and hot. When virtual wins: plugins, run-time configuration, an open set, or ABI boundaries (a stable interface between separately compiled libraries).
