# Fast path: what's different in C++

- **Callbacks are `std::function<void()>`**: a type-erased, copyable callable that stores a lambda with its captures, small ones inline, big ones on the heap. Java has `Runnable`, Python any callable, Go a `func()`; in C++ you choose the price (`std::function` allocates for large captures; C++23's `std::move_only_function` also accepts move-only captures such as `unique_ptr`). Timer-heavy code often uses a plain `void(*)(void*)` plus a context pointer to avoid even that.
- **Node-based lists are the right tool when you hand out stable pointers.** `std::list` nodes never move, and `splice` relinks them between lists in O(1), which is exactly what "collect the due timers, then run them" needs. A `std::vector` of timers would invalidate every pointer in the id index on reallocation, and erasing from its middle is O(n).
- **Reentrancy is the real design constraint.** Event loops (libuv, Boost.Asio, Node.js) face the same problem: handlers that modify the structure that is calling them. Collecting before calling, marking instead of erasing, and releasing resources eagerly on cancel are the standard tools.
- **Lazy deletion** trades a little memory for O(1) cancel; the invariant that keeps it honest ("every slot is visited at least once per revolution, so no dead node survives longer than `slots` ticks") is exactly what `stored_nodes()` lets the tests check.
- **Hierarchical wheels.** One flat wheel is wasteful for far-away timers (they are re-examined every revolution). Linux, Kafka and Netty use *hierarchical* wheels: a fine wheel for the next 256 ticks, a coarser one for the next 256 x 64 ticks, and so on; timers cascade down as their time approaches. Each timer is touched O(levels) times instead of once per revolution.
- **Why not `std::priority_queue`?** It is a fine choice up to some thousands of timers, but it cannot cancel an arbitrary element (you need lazy deletion there too) and each operation costs O(log n). At 500000 connections with a cancel per packet, the constant factor matters.
