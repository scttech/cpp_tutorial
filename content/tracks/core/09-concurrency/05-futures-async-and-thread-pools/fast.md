# Fast path: what's different in C++

- **`std::future<T>` / `std::promise<T>` / `std::packaged_task<R(Args...)>` / `std::async`** (`<future>`). `get()` blocks, returns once, rethrows the stored exception; `wait_for/wait_until` return `future_status`; `shared_future` for several readers; `valid()` is false after `get()`. A promise destroyed without a value gives the future a `broken_promise` error.
- **`std::async(std::launch::async | deferred, f, args...)`**: the default policy lets the implementation choose (maybe deferred, run in `get()`); **the destructor of an async future blocks until the task finishes**, so ignoring the result serializes the code. Prefer an explicit pool/executor for anything beyond a one-off.
- **Thread pool anatomy**: `deque<function<void()>>` + `mutex` + `condition_variable` + `stopping` flag + `vector<jthread>`; `submit` = `packaged_task` in a `shared_ptr` (std::function needs copyable; `std::move_only_function` in C++23) + notify_one; worker = wait(pred) / pop / unlock / run; shutdown = flag + notify_all + (drain queue) + join. Tasks run outside the lock. Declare the thread vector last.
- **Pitfalls**: waiting for a task inside a task of a bounded pool (starvation deadlock); tasks capturing references to locals that die before the task runs; unbounded queues (memory); oversubscription (more threads than cores for CPU-bound work); tiny tasks (overhead > work); exceptions in fire-and-forget tasks have nowhere to go.
- **Beyond the standard**: Boost.Asio `thread_pool` / `post`, Intel oneTBB (`parallel_for`, task arena), OpenMP, `std::execution::par` algorithms (libstdc++ needs TBB), C++26 `std::execution` (senders/receivers), folly/Folly executors.
