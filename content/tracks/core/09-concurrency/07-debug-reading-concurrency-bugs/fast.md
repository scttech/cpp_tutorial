# Fast path: what's different in C++

- **Reading the symptom**: ThreadSanitizer prints `WARNING: ThreadSanitizer: data race` / `lock-order-inversion` with both stacks (use the first frame in your own code); a hang with no output is a deadlock or a lost wake-up (attach a debugger: `gdb -p PID`, `thread apply all bt`; or run under `helgrind`); `terminate called without an active exception` = a joinable `std::thread` was destroyed; `terminate called after throwing ...` = an exception left a thread function; a crash in a thread usually shows in `thread apply all bt`.
- **Causes and cures**: unsynchronized shared data → atomic / mutex / no sharing; opposite lock orders → one global order or `std::scoped_lock`; `cv.wait(lock)` without a predicate → `cv.wait(lock, pred)` (a notify that happened before the wait is lost); unjoined thread → `std::jthread` or `join()` on every path (RAII); exception in a thread → catch and transport with `std::exception_ptr`, `std::promise`/`future`, or `std::async`; plain `bool` stop flag → `std::atomic<bool>` or `std::stop_token`.
- **A sleep is not synchronization.** Timing-based "fixes" only move the race. The standard promises ordering only through mutexes, atomics, condition variables, futures, latches/barriers and thread start/join.
- **Make failures reproducible**: fixed seeds, few threads, `std::latch` to start threads together, stress loops, `--gtest_repeat`; run under TSan in CI; add timeouts to tests so that a deadlock fails instead of hanging the build.
- **Logging**: include `std::this_thread::get_id()`; `std::osyncstream` for whole lines; flush before a risky call so the last line survives a kill.
