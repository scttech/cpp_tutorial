# Fast path: what's different in C++

- **Coroutines are stackless**: a function containing `co_await`, `co_yield` or `co_return` is compiled to a state machine; its locals live in a **frame** (heap-allocated unless the optimizer elides it). They are in the language (C++20, `<coroutine>`), but the library support is minimal: you write (or import) the types.
- **The return type defines the behavior** through `promise_type`: `get_return_object`, `initial_suspend`, `final_suspend` (must be `noexcept`), `yield_value`, `return_void`/`return_value`, `unhandled_exception`; optionally `await_transform`, `operator new` for the frame. `std::coroutine_handle<P>`: `resume()`, `done()`, `destroy()`, `promise()`, `from_promise()`. Awaiters have `await_ready`, `await_suspend`, `await_resume`; `std::suspend_always`/`suspend_never` are the trivial ones.
- **Ownership**: the returned object owns the frame and must `destroy()` it exactly once (RAII, move-only). `final_suspend` returning `suspend_always` keeps the frame for the owner; `suspend_never` destroys it automatically (then the handle must not be touched).
- **Lifetime traps**: reference parameters and references to temporaries dangle across suspensions; take parameters by value; do not `co_await` while holding a lock; be careful about which thread resumes.
- **C++23**: `std::generator<T>` (`<generator>`, `ranges::elements_of` for recursion). **Libraries** for async: Boost.Asio (`awaitable`, `co_spawn`), folly::coro, cppcoro, libunifex, `stdexec`. Coroutines give concurrency without threads (I/O-bound work), not parallelism (CPU-bound work still needs threads).
- **Cost**: a frame allocation per coroutine call (often elided with optimization), an indirect call per resume. Cheaper than a thread (microseconds to create) by orders of magnitude, but not free.
