# Fast path: what's different in C++

- **Warnings are part of the language experience.** The standard requires a diagnostic only for ill-formed code; everything else (the dangerous-but-legal) is up to the compiler's warnings, so you must turn them on. Baseline: `-Wall -Wextra -Wpedantic`. Strict: add `-Wconversion -Wshadow -Wsign-conversion -Wold-style-cast -Wnon-virtual-dtor -Woverloaded-virtual -Wnull-dereference -Wformat=2`. MSVC: `/W4` (or `/Wall`), `/permissive-`, `/WX`.
- **`-Werror`** in CI; `-isystem` (or `SYSTEM` in CMake) for third-party headers so their warnings stay silent; `-Werror=<name>` for individual always-a-bug warnings; `-Wno-<name>` to disable one deliberately.
- **Build with both Clang and GCC** in CI: they find different things (GCC: `-Wmaybe-uninitialized`, `-Wduplicated-cond`, `-Wlogical-op`, `-Wuseless-cast`; Clang: `-Wthread-safety`, `-Wcomma`, `-Wunreachable-code-aggressive`).
- **The classic warning-bug pairs**: assignment in a condition (`if (x = 0)`); a shadowing local that makes an accumulator stay 0; `count = count` in a constructor (a parameter named like the field); an `int` index compared with `size()`; `double` to `int` truncating where rounding was meant; `int` to a narrower type wrapping silently; a `switch` over an enum with a missing case (and **no `default`**, so the warning keeps working when someone adds an enumerator); a variable-length array (a C feature; a big one overflows the stack); an unused parameter (you forgot to use it).
- **Suppress narrowly and say why**: `[[maybe_unused]]` for a parameter that really is not needed, `static_cast` for a conversion you mean, `// NOLINT`/`#pragma` only for a proven false positive, with a comment.
- **Warnings are a baseline, not the end**: the next lesson's tools (`clang-tidy`, `cppcheck`) go further, and the sanitizers find what is only visible at run time.
